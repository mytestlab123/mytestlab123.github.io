:::

Public examples must use sanitized account IDs, ARNs, hostnames, IP addresses, screenshots, and logs.

## 🔄 Workflow storytelling

```text
🔎 Detect
   ↓
🧠 Explain + plan
   ↓
🙋 Human approval
   ↓
⚙️ Narrow deterministic tool
   ↓
✅ Provider verification
   ↓
📦 Evidence
```

The portal should make the **control path** obvious before asking the reader to study implementation details.

## ✅ Steps

<Steps>
1. Start with the engineering problem.
2. Show the architecture or workflow.
3. Explain the important decisions and trust boundaries.
4. Add focused code or configuration examples.
5. Finish with validation, lessons learned, and links to safe public evidence.
</Steps>

## 🔭 What comes next?

The next experiment should be chosen from actual need, not because a plugin exists. Good candidates are:

- Mermaid architecture/workflow diagrams
- tags and taxonomy
- image zoom for architecture/screenshots
- AI-friendly `llms.txt` / Markdown output

The final `amitkarpe.github.io` portal should adopt only features that improve **portfolio storytelling, knowledge discovery, or maintainability**.
