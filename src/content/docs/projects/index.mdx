## 🧭 How to read the portfolio

Look for the repeated engineering pattern rather than only the technology name:

1. **Problem** — what operational/security problem exists?
2. **Boundary** — what is the agent/tool allowed to do?
3. **Approval** — which decisions stay human-controlled?
4. **Execution** — which narrow deterministic path performs the change?
5. **Verification** — what real provider/system evidence proves the result?

That structure will become the default case-study format if the same design is promoted into the final knowledge portal.
