## 🧠 What this project explores

A deliberately small platform-AI learning repository that separates **developer experience, model access, credentials, policy, execution, and evidence** instead of treating them as one AI feature.

The original MVP proved that an application can use a platform key to call one approved model through an internal API without receiving AWS credentials, while a disallowed model is denied and logged. Later experiments add native Bedrock API keys, AgentCore Gateway/Policy, Harness lifecycle work, and a bounded governed MCP workflow.

## 📚 Read this project as four patterns

1. [**Platform architecture**](/kb/agentcore-ai-platform/platform-architecture/) — controlled model access without handing application users general AWS credentials.
2. [**Bedrock API keys**](/kb/agentcore-ai-platform/bedrock-api-keys/) — credential type, model scoping, expiry, audit, and proof boundaries.
3. [**Gateway & Policy**](/kb/agentcore-ai-platform/gateway-policy/) — deterministic authorization and how to prove a denied request did not reach the backend.
4. [**Harness & governed workflow**](/kb/agentcore-ai-platform/harness-governed-workflow/) — managed Harness lifecycle vs a separately governed MCP remediation path.

## Reusable themes

- Model access is a policy decision, not just a model-selection dropdown.
- Credentials need explicit scope, expiry, revocation, storage, and audit rules.
- Gateway/Policy can govern exact tool calls without requiring a model in the proof.
- Harness is useful as a managed execution environment, but a short Harness lifecycle proof is not evidence of a production agent platform.
- Keep **current/proven**, **designed**, and **future** states separate.
