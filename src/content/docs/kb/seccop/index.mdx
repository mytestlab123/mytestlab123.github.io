## 🤖 What this project explores

SecCop is a public secure-agent learning lab. The important engineering idea is that **model explanation and deterministic authority stay separate**.

The repository includes both early synthetic harness experiments and a later operator experience around EC2, S3, and ECR evidence. The current public operator documentation keeps the EC2 server path as the proven live mutation lane; stored-artifact and container paths are presented conservatively as read-only/suggestion lanes unless a separate proof explicitly enables more.

## 📚 Read this project as four patterns

1. [**Secure-agent harness**](/kb/seccop/secure-agent-harness/) — validate the whole plan, authorize deterministically, and fail closed.
2. [**EC2 & SSM remediation**](/kb/seccop/ec2-ssm-remediation/) — exact package proposal, human approval, one-package update, before/after evidence.
3. [**Multi-source operator**](/kb/seccop/multi-source-operator/) — one operator surface across server, stored artifact, and container findings without pretending every source has the same capability.
4. [**Approval & verification**](/kb/seccop/approval-verification/) — proposal-bound approval and provider truth as separate responsibilities.

## Reusable themes

- Model output is untrusted runtime data.
- The entire plan should be validated before the first tool executes.
- Browser/model-visible data can use aliases while raw provider identifiers stay server-side.
- Approval cannot grant a capability the tool registry does not contain.
- A successful API call is not enough; show before/after provider evidence.
