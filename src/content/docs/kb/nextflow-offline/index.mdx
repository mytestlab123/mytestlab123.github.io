## 🧬 What this project explores

A repeatable way to prepare a pinned Nextflow/nf-core workflow online and then prove that a **relocated runtime** can execute using prepared workflow data, plugin state, and mirrored container images without runtime pulls or task networking.

The project is careful about language: this proves **offline emulation on an online host**, not that the host is physically air-gapped.

## 📚 Read this project as four patterns

1. [**Offline architecture**](/kb/nextflow-offline/architecture/) — descriptor → discovery → exact images → private registry → relocated runtime.
2. [**Image discovery & mirroring**](/kb/nextflow-offline/image-discovery-mirroring/) — discover exact container references and distribute them with Skopeo.
3. [**Offline runtime contract**](/kb/nextflow-offline/offline-runtime/) — bundle-local Nextflow state, fresh Podman store, network disabled, pull disabled.
4. [**Validation & evidence**](/kb/nextflow-offline/validation-evidence/) — use the cheapest proof that answers the change and distinguish emulation from true air-gap acceptance.

## Reusable themes

- Discover exact dependencies before isolation.
- Keep pipeline onboarding data-driven through descriptors rather than copying scripts.
- Mirror images registry-to-registry when possible.
- Relocate the bundle so the proof is not accidentally coupled to its build path.
- Make the offline claim match the evidence strength.
