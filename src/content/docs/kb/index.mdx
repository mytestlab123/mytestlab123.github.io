## 🧱 Standard article pattern

Most KB pages follow the same reading path:

1. **Problem** — the engineering problem being solved.
2. **Key idea** — the reusable design decision.
3. **Architecture / flow** — where responsibilities and trust boundaries sit.
4. **Security boundary** — what is deliberately not trusted or allowed.
5. **Verification** — what evidence proves the outcome.
6. **Lessons learned** — what is worth carrying into another system.
7. **Source / evidence** — links back to authoritative public project material.

Detailed extraction now covers **all six featured public projects**. Project repositories remain the implementation authority; this portal is the curated public reading layer.
